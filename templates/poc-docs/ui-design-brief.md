## Design metaphor

The real-world experience that inspires the UI (e.g. editorial cookbook, field notebook, luxury catalog). Must fit the RFP.

## Emotional target

What the user should feel on approved screens.

## Visual personality

3–5 concrete characteristics (not generic adjectives).

## Composition

How important screens are structured (focal layout, rhythm, controlled asymmetry).

## Visual hierarchy

PRIMARY → SECONDARY → SUPPORTING → UTILITY. What dominates; what supports.

## Imagery / media strategy

First-class imagery only when RFP files exist or the plan allows user upload. Otherwise honest treatments: `TypographicCover`, initials, charts/timelines/maps from UI primitives. No stock or faux photos.

## Interaction concept

One memorable interaction **only if** a named capability supports it. Otherwise a memorable visual/compositional moment. Motion communicates state, progress, navigation, cause/effect, or spatial relationship — not decoration.

## Signature moment

What a user remembers 10 seconds after seeing the POC. Fail if the answer is “the colors were nice” or “it looked modern.”

## Content density

How populated the interface should feel (low | moderate | high) and how realistic fixtures vary.

## Visual rhythm

How section height, card size, density, media ratio, type scale, alignment, grouping, and emphasis vary. Avoid card → card → card.

## Controlled asymmetry

Featured vs supporting, offset media, editorial relationships — usable and intentional.

## Responsive behavior

How the concept (anchor, hierarchy, signature moment) adapts on small viewports. Do not collapse into a generic stacked list that loses identity.

## Component direction

How cards, buttons, navigation, forms, tables, badges, empty/error/success, and media express the selected metaphor.

## Anti-patterns (this design)

Things this concept specifically avoids (generic SaaS template, glassmorphism, purple/blue AI styling, empty heroes, identical card grids, cosmetic-only novelty, …).
